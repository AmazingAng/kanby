# GitHub delivery pilot evidence

The workflow proposal was accepted in chat. The [executable specification](github-delivery-pilot-spec.md) was implemented autonomously and did not receive separate approval.

- `tests/github-automation.test.ts` exercises signed GitHub deliveries, a real SQLite database with D1-compatible bindings, and the Issue import and link routes. It covers URL and activity imports returning the same card, refusal of unselected repositories, migration of an overwritten Issue and its existing PR/CI record, removal of one link, repository-wide ambiguity and project-qualified references, review requests, rejection of a non-member reviewer, the default-branch requirement, multi-PR and replay behavior, and protection of a later manual handoff.
- `KANBY_XAPI=1 KANBY_PUBLIC_ORIGIN=https://kanby.dev npm run gauntlet` passed 20/20 layers. Both full and shuffled suites passed 360 tests across 46 files. The handoff module had 100% line and function coverage, 95.45% statement coverage, and 85.71% branch coverage. The mutation gate killed 126/126 mutants, including four covering the pilot. Production dependency audit reported zero vulnerabilities. The xAPI Worker build and schedule checks passed.
- The initial RED run reproduced Issue replacement and rejected the pilot settings request. A release run caught a React effect writing state and another caught a legacy mutation selector that matched the newly added project-qualified marker. Both were corrected before the final run. The sandboxed CLI run lacked loopback access; the release run used permitted loopback access.
- The verified xAPI preview source tree before adding this evidence file had SHA-256 `052165af2a95b30ac289f804d9e980b68329cf8be83c64c1b61d84ef3a04320b`. Preview and production D1 resources were verified to be distinct. The native migration receipt reported `0021_github_delivery_pilot.sql` as `APPLIED` on preview D1 with SHA-256 `afbb2592fa4f25b80f1050eca9de5f27f2d90d0dded83331431a45376ebf63be`.
- Live GitHub readback showed `kanby-app` already has read access to Issues and Pull requests. The registration was subscribed to Issue, Pull request, Push and Workflow run events. A production pilot also needs the Pull request review subscription. The tests used local signed events and do not claim a real GitHub review was delivered to an xAPI project. See the [rollout steps](../GITHUB_DELIVERY_PILOT.md).
